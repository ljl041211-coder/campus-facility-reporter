# Campus Facility Reporter

A mobile Progressive Web App (PWA) for reporting damaged outdoor facilities on a university campus or any large outdoor site. When a student spots a problem, such as a broken street light, damaged pavement, an overflowing bin, damaged seating, a road safety hazard or a blocked accessible ramp, they take a photo, the app records the location, and the report is saved on the phone. Reports are shown in a list and on a campus map. Open problems use animated cartoon markers, and a student can mark a report as resolved once the problem has been fixed.

## Tech stack

- [React](https://react.dev/) with [Vite](https://vite.dev/) – UI components and development server
- [Dexie](https://dexie.org/) and `dexie-react-hooks` – IndexedDB storage and live queries
- [react-webcam](https://www.npmjs.com/package/react-webcam) – camera access
- [Leaflet](https://leafletjs.com/), [React Leaflet](https://react-leaflet.js.org/) and [OpenStreetMap](https://www.openstreetmap.org/) tiles – campus map
- [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) – web app manifest and service worker
- [Vercel](https://vercel.com/) – HTTPS hosting (required for camera and geolocation on a phone)

## Getting started

### Requirements

- Node.js 20.19 or newer (check with `node -v`)
- npm (comes with Node.js)
- Git
- Google Chrome (recommended for DevTools: Application tab and Sensors panel)

### Install and run

```bash
git clone <your-repository-url>
cd campus-facility-reporter
npm install
npm run dev
```

Open the local address printed in the terminal (usually http://localhost:5173).

### Test on a phone during development

`npm run dev` also prints a Network address (for example http://192.168.x.x:5173). A phone on the same Wi-Fi can open it, but camera and geolocation only work over HTTPS (or on localhost), so test those features on the Vercel deployment.

### Build and preview the production version

```bash
npm run build
npm run preview
```

The service worker is only generated by `npm run build`, so test installation with `npm run preview` or on Vercel, not with `npm run dev`.

### Deploy to Vercel

1. Push this repository to GitHub.
2. In Vercel, choose **Add New → Project** and import the repository.
3. Vercel detects Vite automatically (build command `npm run build`, output folder `dist`). Click **Deploy**.
4. Open the HTTPS address on your phone and choose **Add to Home Screen** (iPhone, Safari) or **Install app** (Android, Chrome).

## How to use

1. **Create** – tap **Report**. The app asks for your location straight away (allow it when the browser asks). Tap **Take photo** to use the camera, or **Choose a photo** to pick one from your gallery; both the photo and the location are optional. Then choose the type of problem, write a short description (at least 10 characters) and, if you like, a location note such as "left of the library entrance". Tap **Save report**. If something is missing, the form shows a message under that field.
2. **Read** – tap **My reports** to see all reports, newest first. Tap a report to open its details.
3. **Update** – on the details screen, tap **Edit report** to change the text, retake or remove the photo, or update the location, or tap **Mark as resolved** once the problem has been fixed. A resolved report can be reopened with **Reopen report**.
4. **Delete** – on the details screen, tap **Delete report** and confirm. The report and its photo are removed from the phone.
5. **Map** – tap **Map** to see every report that has a location. Red pins need repair; grey pins with a ✓ are resolved. Tap a pin for a summary and **View details**. Tap **Show my location** to see where you are. The map tiles need an internet connection; without one, use **My reports**.

Reports are stored on the phone, so they are still there after you close and reopen the app.

The camera and location only work on a secure (HTTPS) page or on localhost. If you deny a permission, the app explains how to allow it again, and you can still choose a photo from the gallery or describe the place in the location note.

## Data model

Reports and photos are stored in one IndexedDB database (`campusReporterDB`) in two tables linked by the report id, so a report and its photo can be created or deleted together. See the comments in `src/db.js`.
